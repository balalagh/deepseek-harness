# Agent Note: the art-exam query tool package

Status: implemented

[English](2026-09-30-art-query-tool-package.md) | 中文

## Problem

需要回答艺术类高考招生问题的部署，要在自己的招生工作簿上给模型提供工具。工作簿不在任何检出目录里，含六个 sheet、33,656 条投档明细，能回答五类不同问题：各省政策规则、按院校专业组的投档明细、哪些院校仍可组织校考、每个统考类别对应哪些本科专业、以及各招生模式有何不同。这个形状不是单个工具能覆盖的，而其中任何一部分都不属于仓库——数据是某个部署的快照。

已有的高考栈回答的是结构不同的问题：`gaokao-api` 托管一个以 MySQL 为后端的 FastAPI 服务，`tool-gaokao-query` 调它的端点。照搬这个形状，就意味着为一份文件数据再加一个常驻服务、一个端口和一套进程生命周期。

## Decision

`packages/gaokao/tool-art-query/` 提供五个面向模型的工具——`query_art_policy_matrix`、`query_admission_detail_2026`、`query_school_exam_list`、`query_major_catalog`、`query_admission_mode_overview`——它们读 `Config.dataPath` 指定的同一份数据集。**包内不携带数据，也不启动服务**：数据集是部署数据，由 `packages/gaokao/tool-art-query/scripts/convert_art_xlsx.py` 从工作簿生成，并由挂载它的组合指明路径。

四点让「快照」这一形态可用：

- **工具在内存里筛选。** 数据集在第一次调用时载入并常驻，因此除首次之外查询不再产生 I/O。`Config.maxRows`（默认 200）限制每个列表结果的行数，而 `count`、`returned`、`truncated` 仍如实报告被省略了多少。
- **载入以 mtime 为键。** 重新生成数据集会被同一进程的下一次调用读到，因此刷新部署数据不需要重启。
- **文件边界做校验，行字段做归一。** 解析出的文档先过 `schemastery` 校验（五个集合必须存在），每次读字段都归一成声明的类型：类型不对的单元格读作缺失，而不是在注册表那里让输出 schema 报错。文件缺失或结构不对时，第一次调用就带出指明该文件的错误。
- **类别归一放在转换脚本里。** 工作簿把同一个统考类别写出 84 种写法（`音乐类`、`音乐表演类(器乐)`、`艺考类本科统考E（音乐表演（器乐）类）` …）。转换脚本额外写入内部字段 `category` 承载归一类别，工具既匹配原值也匹配归一值，并先把全角括号折成半角。归一不上的值落入 `其他` 并记在 `meta.categoriesUnmapped` 里，使新写法在数据集里可见，而不是被静默归档。

转换脚本默认只导出 2026 年的投档明细，因为该 sheet 还带着 7,007 条其它年份的行、其批次名标注为兜底记录；`--years all` 可放宽导出范围，此后工具只接受数据集实际携带的年份。

## Alternatives considered

**在 `gaokao-api` 旁边再加一个 FastAPI 服务。** 它会复用高考栈已经验证过的 host 行形态：一行派生 `uvicorn`、一次健康检查、工具包里的 HTTP 客户端。它落选是因为数据是 2.5 MB 的文件而不是可查询的存储：服务会为五个查询加上一个端口、一套进程生命周期、一份健康契约和一步部署动作——而这些查询用常驻内存筛选回答得更快，同时它会把工作簿解析放到每次调用的关键路径上。

**保持为 preset 内的本地插件文件。** 3081 实例最初就是这么跑的：用户 preset 里的 `plugins/art-query.mjs` 读它旁边的数据集。它能用，但代码不在版本控制里，也不在任何门禁内——没有单测、没有 README 契约、没有目录条目——而它读的部署数据才是应当留在本地的部分。提升后的包保留了这一分工：代码进仓库，数据留部署。

**让工具在 Node 里直接解析工作簿。** 那样需要引入 XLSX 读取库（仓库原本没有这个依赖），并为每次调用付出解析 2.5 MB 工作簿的代价。一次性转换让运行时零依赖、查询路径更便宜。

**把工作簿导入现有 MySQL。** 这样筛选可以用 SQL 表达并复用 `gaokao-api`。它落选在归属上：工作簿是某个部署的研究产物，没有 schema 负责人，列是异质的长文本与半空的数字，导入它会让「改一份研究文件」变成「做一次数据库迁移」。

## Consequences

招生工作簿查询现在有了受版本控制、有测试、进目录的归属，同时没有给部署增加服务、端口或进程生命周期。

代价是转换步骤不被任何 Node 侧门禁覆盖。转换脚本需要 Python 与 `openpyxl`，刻意不在发布的 `files` 里，也无法被 `pnpm run test` 覆盖；工作簿格式变化在重跑脚本时才暴露，而不是在 CI。忘记这一步的部署会出现「schema 可用、调用失败」——失败信息里带着数据集路径，这是在不携带数据的前提下能给出的最响亮信号。行内容做归一而不做校验，因此类型不对的字段读作缺失；另一条路（载入时校验全部 26,648 行）会用一次全表 schema 遍历去挡一个转换脚本自身测试都造不出的情况。

五个工具也继承了工作簿本身的不齐整：缺少汇总口径、很多省份的投档明细没有专业、`其他(待归)` 与 `艺术(区内)` 共 7 行匹配不上任何归一类别。这些是数据事实，工具以 `（未收录）` 与 `meta.categoriesUnmapped` 如实呈现，而不是抹平。

## Testing

`packages/gaokao/tool-art-query/tests/art-query.spec.ts` 在真实工具注册表上装载本包，每个用例写入一份 fixture 数据集，钉住：注册结果、五个 schema 的参数、省份覆盖报告、归一类别匹配、院校包含匹配、分数区间筛选、缺分值排在最后的降序、`maxRows` 截断与其截断报告、不支持年份的错误、数据集缺失的错误，以及 mtime 驱动的重新载入。`scripts/gen-tool-catalog.ts` 会装载本包（用一个没有任何工具会读的占位 `dataPath`），使五个 schema 无法与 `docs/tool-catalog.md` 漂移。
